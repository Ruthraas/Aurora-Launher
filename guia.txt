# CONTEXTO

Projeto: **Aurora Launcher by ATS**, launcher de Minecraft Java (Tauri 2 + Rust no backend, React + TypeScript + Vite + Tailwind + shadcn/ui no front). Já existem, ou serão criados, os módulos: instâncias, downloads paralelos com SHA1, loaders (Fabric/Quilt/Forge/NeoForge) e provedores Modrinth/CurseForge (atrás de uma trait `ModSource`). Antes de codar, leia o repositório e o CLAUDE.md e reaproveite o que já existe. Não recrie o que já está pronto.

Esta tarefa tem 3 partes: **(A)** novo visual, **(B)** fluxo "Adicionar mod" na tela Descobrir, **(C)** fluxo "Baixar modpack" na tela Descobrir.

# PARTE A: IDENTIDADE VISUAL (profissional, minimalista, responsivo)

Troque a paleta atual. Objetivo: aparência de produto profissional, calma e agradável, sem gradiente chamativo.

Tokens (CSS variables no tema, expostos ao Tailwind):
```

--surface:   #141a23   /* painéis, sidebar */

--accent-fg: #06201c   /* texto sobre o accent */

--warning:   #fbbf24
```
Regras:
- Minimalista: superfícies chapadas, bordas de **1px** com `--border`, cantos 10-14px, sombras quase inexistentes.
- O accent aparece só em: botão primário, foco, item ativo da navegação e barras de progresso. Gradiente permitido apenas nas barras de progresso (accent → `#818cf8`).
- Fontes: Sora (títulos) + DM Sans (texto).
- Contraste mínimo WCAG AA. Alvos de clique ≥ 44px. `:focus-visible` sempre visível.
- **Responsivo** por largura da janela: ≥900px sidebar de ícones à esquerda e grid auto-fill; 640-900px margens menores e layouts de 2 colunas viram 1; <640px sidebar vira barra inferior, listas em coluna única, modais viram bottom sheet em tela cheia.
- Sem hex hardcoded nos componentes: use só os tokens.

# PARTE B: DESCOBRIR > ADICIONAR MOD

Em cada resultado de **mod** (Modrinth/CurseForge unificados), botão **"Adicionar"**. Ao clicar, abre um **modal** (shadcn Dialog) com o título "Adicionar {mod} a uma instância".

**Conteúdo do modal:** lista de todas as instâncias do usuário. Para cada uma, o backend calcula um status:

1. **Compatível**: o loader da instância é suportado por alguma versão do mod **e** essa versão suporta a versão do Minecraft da instância. Linha normal, com checkbox. Mostrar a versão do mod que será instalada (ex.: "v0.6.2").
2. **Já instalado**: o mod (mesmo projeto) já existe na instância. Linha **esmaecida** (opacity ~0.45), **sem checkbox**, `aria-disabled="true"`, não clicável, com o texto "Já instalado" + versão atual. Nunca dá para selecionar.
3. **Incompatível**: loader ou versão do jogo não suportados. Ficam num grupo recolhido "Incompatíveis (n)", esmaecidas, não selecionáveis, com o motivo ("Requer Fabric", "Sem versão para 1.20.1").

Comportamento:
- Seleção **múltipla** entre as compatíveis. Se houver só **uma** compatível, ela já vem marcada.
- Botão primário do rodapé: "Adicionar a {n} instância(s)", desabilitado com 0 selecionadas.
- **Dependências obrigatórias**: resolver e mostrar "Também será instalado: X, Y" (pular as que já existem na instância). Dependências opcionais só listadas, nunca instaladas sozinhas. Dependência incompatível bloqueia aquela instância, com motivo.
- Se **nenhuma** instância for compatível: estado vazio com o botão "Criar instância compatível", que abre o fluxo de nova instância já preenchido com o loader e a versão do jogo mais recente suportados pelo mod.
- Estados de loading (skeleton), erro (com "Tentar de novo") e sucesso (toast + a linha passa a "Já instalado").
- Acessibilidade: focus trap, Esc fecha, foco volta ao botão que abriu, navegação por teclado, `aria-live` para o resultado.

**Detecção de "já instalado"** (regra de negócio importante):
- Cada instância mantém um arquivo de estado `mods.lock.json` com, por mod: `source`, `project_id`, `version_id`, `file_name`, `sha1`, `installed_at`, `explicit: bool` (se veio de escolha do usuário ou de dependência).
- Comparar por `(source, project_id)`. Como o mesmo mod pode existir no Modrinth e no CurseForge com IDs diferentes, usar **fallback por SHA1 do arquivo** e, em último caso, por nome de arquivo normalizado.
- Mods colocados manualmente na pasta `mods/` também devem ser reconhecidos por SHA1 (consultar o endpoint de busca por hash do Modrinth e cachear).
- Fora de escopo agora: atualização de versão de mod já instalado (deixar a interface preparada, sem implementar).

# PARTE C: DESCOBRIR > BAIXAR MODPACK

Em cada resultado de **modpack**, botão **"Baixar"** (ícone de download). Ao clicar, abre um modal/drawer de confirmação com:
- Nome da instância (campo editável; padrão = nome do modpack; se já existir uma instância com esse nome, sugerir "Nome (2)").
- Seletor da versão do modpack (padrão = última estável).
- Resumo somente leitura: versão do Minecraft, loader + versão do loader, quantidade de mods, tamanho estimado do download, RAM sugerida.
- Botão primário "Baixar e criar instância".

Ao confirmar, o launcher **cria a instância imediatamente** (aparece em Instâncias com estado "Instalando" e barra de progresso) e executa um job em background, **cancelável**:
1. Buscar os metadados da versão do modpack.
2. Criar a instância com o nome escolhido e o ícone do modpack. Guardar a **origem** (`modpack_source`, `project_id`, `version_id`) para futuras atualizações.
3. Instalar a versão do Minecraft e o Java necessários (usa o cache global).
4. Instalar o loader exatamente na versão que o pack pede.
5. Baixar todos os arquivos em paralelo, com verificação de hash, retry e escrita atômica.
6. Extrair `overrides/` (e `client-overrides/` no caso do .mrpack) **com proteção contra zip-slip**.
7. Gerar o `mods.lock.json` da instância.
8. Finalizar: estado "Pronta".

Formatos (**verifique a documentação oficial antes de implementar, não assuma campos**):
- **Modrinth `.mrpack`**: `modrinth.index.json` (dependências de minecraft e loader, arquivos com hashes e URLs, `env`), pasta `overrides/`.
- **CurseForge**: `manifest.json` (versão do Minecraft, `modLoaders`, lista de `projectID`/`fileID`), pasta `overrides/`. Mods com `downloadUrl: null` não podem ser baixados automaticamente: **não falhar o job**. Concluir o resto, marcar a instância como "Incompleta" e mostrar uma lista "Baixe manualmente" com o link de cada mod. Depois que o usuário colocar o arquivo, revalidar.
- Chave de API do CurseForge **só via proxy**, nunca no binário.

Falhas: em erro fatal, oferecer "Tentar de novo" (retomando o que já foi baixado) ou "Remover instância", sem deixar pasta pela metade. Nunca `unwrap()` em caminho de produção.
